# Fraud Ring Detector
### Event-Driven Fraud Detection System | Streaming Analytics Engine

Fraud Ring Detector is a Java and Spring Boot based application designed to identify suspicious financial transactions and potential fraud patterns. It provides a security-focused dashboard for monitoring transactions, reviewing fraud alerts, and exploring suspicious activity using role-based access control.

The project demonstrates how backend development, transaction validation, fraud detection rules, REST APIs, and authentication can be combined to build a financial fraud monitoring application.

## Project Overview

Financial fraud can involve unusually large transactions, rapid money transfers, repeated activity, and circular transfers between accounts. Detecting these patterns can help analysts identify potentially suspicious behaviour for further investigation.

Fraud Ring Detector provides a foundation for exploring these scenarios through a web-based dashboard backed by a Java application.

## Features

- **Transaction Management:** View and submit financial transactions through REST APIs.
- **Fraud Detection:** Identify suspicious transaction patterns using configurable detection rules.
- **Fraud Alerts:** Review alerts generated by the detection service.
- **Role-Based Access Control:** Restrict application features and API access based on the authenticated user's role.
- **Secure Authentication:** Use Spring Security form-based login with BCrypt password encoding.
- **Interactive Dashboard:** Access transaction summaries, alerts, and other project features through a dark-themed web interface.
- **Input Validation:** Validate transaction details and reject invalid or duplicate transaction IDs.
- **Session Logout:** End the authenticated session through the logout flow.

## Application Architecture

The application follows a layered structure:

1. **Frontend:** HTML, CSS, and JavaScript provide the login page and security dashboard.
2. **Controller Layer:** Spring controllers expose authentication, transaction, and fraud alert endpoints.
3. **Service Layer:** Services handle transaction management and fraud detection logic.
4. **Model Layer:** Java classes represent transactions and fraud alerts.
5. **Security Layer:** Spring Security manages authentication, session handling, and role-based authorization.

## User Roles

The application defines three roles with different permissions.

| Role | Permissions |
|---|---|
| Admin | View transactions, review fraud alerts, and submit transactions |
| Analyst | View transactions and review fraud alerts |
| User | Submit transactions; transaction and alert viewing endpoints are restricted |

Access is enforced by Spring Security at the backend, rather than relying only on hiding dashboard elements.

## Fraud Detection Rules

The project includes detection logic for suspicious transaction scenarios such as:

- **Large Transactions:** Transactions exceeding a configured amount threshold.
- **Rapid Inflow and Outflow:** Suspicious patterns involving money entering and leaving an account within a short period.
- **Repeated Rapid Transactions:** Multiple transactions occurring within a short time interval.
- **Circular Transfers:** Transfers that form a potential cycle between accounts.

These rules are intended to flag transactions for investigation. An alert does not, by itself, establish that fraud has occurred.

## Prerequisites

Install the following before running the project:

- Java Development Kit (JDK)
- Maven Wrapper included in the repository
- Git (optional, for cloning the repository)

Check your Java installation:

```powershell
java --version
```

## Getting Started

### 1. Clone the repository

```powershell
git clone https://github.com/mfm-shirin/fraud-ring-detector.git
cd fraud-ring-detector
```

### 2. Configure environment variables

The application expects three environment variables for its in-memory demo accounts:

- `ADMIN_PASSWORD`
- `ANALYST_PASSWORD`
- `USER_PASSWORD`

In PowerShell, set them before starting the application. Use your own strong, unique passwords.

```powershell
$env:ADMIN_PASSWORD = "ChooseYourAdminPassword"
$env:ANALYST_PASSWORD = "ChooseYourAnalystPassword"
$env:USER_PASSWORD = "ChooseYourUserPassword"
```

Do not commit real passwords, `.env` files containing secrets, or other credentials to GitHub.

### 3. Compile the project

```powershell
.\mvnw.cmd clean compile
```

### 4. Run the application

```powershell
.\mvnw.cmd spring-boot:run
```

### 5. Open the application

Visit the following URL in your browser:

**http://localhost:8080/**

The login page will allow you to authenticate with one of the configured accounts.

## API Endpoints

The application exposes REST endpoints for its core features.

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/api/transactions` | Retrieve transactions; Admin and Analyst access |
| POST | `/api/transactions` | Submit a transaction; Admin and User access |
| GET | `/api/fraud-alerts` | Retrieve fraud alerts; Admin and Analyst access |
| GET | `/api/auth/me` | Retrieve the current authentication information, subject to its controller implementation |
| GET | `/api/csrf` | Retrieve CSRF token information, if enabled by the application configuration |

Authenticated requests are subject to the application's Spring Security rules. POST requests may also require the appropriate CSRF token.

## Current Limitations

- Transaction and alert data are currently held in memory and may be lost when the application restarts.
- The demo users are configured in memory rather than stored in a persistent user database.
- Fraud detection is based on implemented rules and is not a production-grade financial fraud detection service.
- The current implementation is intended for learning, demonstration, and further development.
